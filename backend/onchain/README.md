# On-chain verification of Huma pages

`HumaPagesV3` checks a page's zero-knowledge proofs on Base and records the page. The six verifiers are generated by
Barretenberg (`bb write_solidity_verifier -t evm --optimized`) from Huma's **existing** long3 circuits (chunk and final
for each page size, 1024, 4096 and 10000 characters). No circuit is changed or added.

- The browser proves a page as before. After Finish, **Verify On-Chain** proves the same page again in the EVM format
  (the same circuits, a keccak transcript, `frontend/write/prove.mjs` `proveForChain`). The writing never leaves the
  browser; only the proofs and the page's public statement do.
- The server's relayer wallet submits them (`frontend/onchain.mjs`, `POST /api/onchain/pages`), so writers need no
  wallet or gas. Each call is simulated first: a proof that wouldn't verify costs nothing.
- `HumaPagesV3` routes by the statement's text size to that size's verifier pair and checks every part proof and the
  final proof. It also checks the part linkage the reader checks: the genesis part comes first, each part starts where
  the last ended, and the final state is where the last part ended. It then records
  `keccak256(statement) → (block, parts, tier, submitter)` and emits `PageVerified`. Up to 12 parts go in one transaction;
  a longer page uses `submitParts` batches and then `submitFinal`.
- `/verify` shows **Verified on-chain** for a page whose statement is recorded, with the transaction and a `cast`
  command to ask the contract yourself.

**Not checked on-chain yet** (Huma's reader still checks them in the browser):
- the P-256 signatures over the checkpoint and presence roots;
- the nonce ↔ capture-key binding and the event digest (Poseidon2);
- passkey assertions.

## Use

Install `forge-std` into `lib/` once (`forge install foundry-rs/forge-std --no-git`). Then:

```sh
forge test                                   # 35 tests, real EVM proofs in test/fixtures (all three page sizes)
forge build && HUMA_RELAYER_KEY=0x… node deploy.mjs --yes        # deploy: the 6 verifiers + HumaPagesV3
PAGES=0x… HUMA_RELAYER_KEY=0x… node submit.mjs <proof dir> --yes  # submit a page made by bb (part<i>/, final/)
```

Turn it on in the server's env (`.env.example`): set `HUMA_RELAYER_KEY` and `HUMA_ONCHAIN_CONTRACT`, plus `HUMA_CHAIN`,
which is `base-sepolia` by default. `keys/` holds the EVM verification keys. They are pinned in
`frontend/write/pins.mjs` (`EVM_KEYS`), and `write/build.mjs` copies them into `dist/write`.
